# 声纹

> 2026-10-15 起。声纹存在 EchoMind 服务器上，同一家公司的电脑共用。

**一句话**：给会议里的说话人命名时勾选「记住声音」，本人在飞书卡片上点同意后，EchoMind 就记住这个人的声音。以后的会议转写完，认得出的说话人会自动标上名字，显示「声纹识别 xx%」。

## 规则

- **本人同意才保存**。声纹属于敏感个人信息，有两种方式算本人同意：
  - 本人在机器人发来的飞书卡片上点「同意」。
  - 本人在自己的 EchoMind 里给自己命名，勾选「记住我的声音」。这个勾默认不勾。
- **同意之前，声音不离开录音的电脑**。给同事命名并勾选「记住声音」以后：
  - EchoMind 只发出同意卡片，声音特征留在这台电脑上。
  - 本人同意后，这台电脑在几分钟内把这段声音的特征上传（EchoMind 开着时每 5 分钟看一次）。
  - 上传前会再核对一次：这场会里那位说话人还叫这个名字才上传。后来改了名字，或者重新区分了说话人，这段声音就不传了。
  - 等待期间，电脑上只记着「哪场会、哪个说话人、谁命名的」（`voice-pending.json`），不存声音。30 天没回复就作废。
  - 只有当初命名的那个登录（同一个人、同一家公司）会上传；换成别的公司登录时，这些记录原样留着。
- **只存声音特征**。声纹是一串描述声音特点的数字（192 个），不是录音，也还原不出说了什么。服务器用 `ECHOMIND_DATA_KEY` 加密保存。
- **声纹不出服务器**。新会议转写完，电脑把每个说话人的声音特征发给服务器，问这是谁。服务器比对完就丢掉，不保存，也不写日志。各台电脑拿不到同事的声纹。
- **随时可以删**：
  - 本人：在那张卡片上点「删除我的声纹」，或在「人员与声纹」页删除自己的。
  - 同事：在「人员与声纹」页也能删除别人的。
  - 删除会连同意记录一起删掉，再要保存就得重新同意。
- **不同意也没关系**。本人点「不同意」以后：
  - 已经存下的部分会一起删掉。
  - 命名时不再提供「记住声音」。
  - 「人员与声纹」页上可以「再问一次」，一天最多一张卡片。
- **只在本公司内**。每家公司的声纹只用来认本公司的人；别家公司的人看不到，也删不了。
- **外部联系人不保存声纹**。

## 同意卡片

由这家公司的飞书应用机器人发出，私聊给本人。卡片上写明：

- 谁、在哪场会里把一段声音标成了这个人。
- 保存的是什么：声音特征，不是录音。
- 用来做什么，以及可以随时删除。

卡片有四种状态，按钮按了以后，卡片会直接变成新的状态：

| 状态 | 按钮 |
| --- | --- |
| 等待回复 | 同意 / 不同意 |
| 已同意 | 删除我的声纹 |
| 没有同意 | 同意 |
| 已删除 | 同意 |

只有本人能按自己卡片上的按钮。飞书只等 3 秒：服务器 2.5 秒内没处理完，就当没按过，什么也不改，飞书会提示本人重试。

### 卡片要用到的飞书设置

每家公司的飞书应用都需要以下设置，做法见 `docs/companies.md`：

- 机器人能力；
- `im:message:send_as_bot` 权限；
- 长连接方式的「卡片回传交互」回调（card.action.trigger）；
- 收卡片的人在应用的可用范围里。

按钮点击怎么回到服务器：

- worker 给每家公司的应用各开一条飞书长连接（`apps/server/src/feishu/connections.ts`），按钮点击从这里回来。服务器不需要域名，也不需要公网回调地址。
- 每分钟按「公司管理」里的变化增减长连接：新添加的公司、停用的公司、换了 App Secret 的公司。
- 连接 15 秒没建立，或者发出心跳后 30 秒没有回音，就断开重连，免得连接「看着还在、其实不通」时收不到按钮点击。
- 同一个应用只能有一个进程连着。本地开发时，不要用正式公司的应用跑 worker，否则按钮点击可能被本地进程收走。

## 认人怎么判断

- 每个说话人取最多 60 秒的声音，只用没有别人插话的片段。
- 和本公司已同意的声纹逐个比对（余弦相似度）。满足下面两条才认，认错比不认更糟，因为待办会跟着名字走：
  - 最像的那个人相似度不低于 **0.6**；
  - 比第二像的人高出至少 **0.05**。
- 一个人在一场会里最多对应一个说话人。已经有名字的说话人（比如线上会议里麦克风上的「我」）保持不变。
- 说话少于 3 秒的人不参加比对。一段声音少于 5 秒，不能存进声纹。
- 给已经有声纹的人再命名时，这段声音会加进去，让识别更准。和已存声纹差别太大的声音（相似度低于 0.3）会被拒绝，多半是标错了人。
- 声纹会慢慢跟着新声音调整：旧声音最多按 300 秒计权重。

在 macOS 合成语音做的测试会议里，同一个声音在两场会之间的相似度是 0.98 到 0.99，不同声音在 0.25 到 0.36 之间。同一个合成器的两个声音（Eddy 和 Grandma）互相能到 0.75，但仍然靠 0.05 的领先差距分对了。真人在不同房间、不同设备上的相似度会低一些，阈值要用真实会议再调。测试是 `native/transcriber/tests/synthetic.rs` 里的 `voices_are_recognised_in_another_meeting`。

## 接口

服务端（都要登录，只作用于自己公司）：

| 接口 | 说明 |
| --- | --- |
| `GET /v1/voiceprints` | 本公司有声纹或发过卡片的人 |
| `POST /v1/voiceprints/:openId/ask` | `{ meeting? }`，发同意卡片；同一个人 24 小时内只发一次，每人每小时最多发 20 张 |
| `POST /v1/voiceprints/:openId/samples` | `{ vector, seconds }`，加一段声音；别人的要先同意，自己的不用 |
| `DELETE /v1/voiceprints/:openId` | 删除声纹和同意记录 |
| `POST /v1/voiceprints/match` | `{ voices: [{ speakerId, vector, seconds }] }`，返回 `{ matches: [{ speakerId, openId, score }] }`，不保存 |

错误码：

- `consent_needed`：还没同意。
- `asked_recently`：24 小时内发过卡片。
- `not_same_person`：和已存声纹差别太大。
- `too_short`：声音不到 5 秒。
- `self`：给自己发卡片。
- `not_found`：本公司没有这个人。

桌面端命令见 `docs/desktop-ipc.md` 的「Voiceprints」一节。

## 数据

- 表 `voiceprints`（迁移 `0004_voiceprints.sql`），每人一行，字段：
  - 状态：asked、agreed 或 declined；
  - 谁发的卡片、发卡时间、卡片的消息 ID；
  - 本人回复的时间；
  - 加密的声纹、样本数、总秒数。
- 删除就是删掉这一行。
